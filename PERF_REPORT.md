## Зависимости — зачем

- `stats-gl`: диагностическая панель, только в динамическом чанке `?perf`.
- `pixelmatch`: попиксельное сравнение эталонов, включая anti-aliasing.
- `pngjs` и `@types/pngjs`: чтение/запись PNG и типы для тестовых скриптов.
- `ssim.js`: SSIM и кропы для perceptual-экспериментов.
- `lighthouse`: отдельный лабораторный mobile-аудит.
- `@next/bundle-analyzer`: состав Webpack-бандла; обычная сборка остаётся Turbopack.

## Контракт измерений

- Visual: `?freeze=12`, качество фиксировано на дефолтном 1 **только в freeze**.
- Существующие seed звёзд/сада сохранены. Бабочки имеют аналитические, не случайные траектории.
- Freeze фиксирует время шейдеров, камеру, затухания, историю бабочек и отключает скан/клик-события.
- Playwright фиксирует DOM-анимации отдельно; одинаковые viewport, DPR, Chrome и координаты указателя.
- Строгий первый повтор выявил шум GPU-растеризации DOM-градиентов: mobile до 8.91524% различающихся пикселей, в основном ±1 канал. Порог pixelmatch НЕ ослаблен.
- Visual Chrome теперь использует `--disable-gpu-rasterization` только для DOM/CSS и свежий документ на кадр. WebGL остаётся hardware ANGLE. Проба проблемного mobile 50% повторилась с diff 0 и SSIM 1.
- Live perf/trace/Lighthouse не используют этот raster-флаг; предварительные снимки архивированы в `perf/results/initial-visual/`, не являются принятым эталоном.
- Performance: живое время и существующая автодеградация; её уровни записываются, не скрываются.
- RAF-интервалы — не presented FPS. CPU submission — не GPU execution.
- GPU: асинхронные disjoint timer queries, без `gl.finish`, без вложенных запросов; полные кадры и проходы измеряются на разных кадрах.
- `renderer.info.memory` — счётчики ресурсов, не объём VRAM; heap измеряется отдельно.
- Профили последовательные, во время измерений нет скриншотов. Trace и Lighthouse — отдельные прогоны.
- 120 Гц нельзя честно доказать подменой времён RAF. Если реальная частота не доступна, профиль помечается неподтверждённым.

## Результаты

**Промежуточный checkpoint, не итоговый baseline.** Production build и TypeScript прошли;
системный Chrome использует Intel Arc через ANGLE/D3D11, GPU timer queries доступны;
физический экран 3072×1920, 120 Гц подтверждён Win32_VideoController.
Полный повтор 33+33 кадров, затем живые три профиля, trace, Lighthouse и bundle-load запущены последовательно.
Цифры и топ-5 заполняются только после завершения. До итогового baseline и отчёта переход к Фазе 1 запрещён.

Статическая проверка всех групп гипотез: [reports/perf-phase0-audit.md](reports/perf-phase0-audit.md).
Субъективная плавность, подтверждённая пользователем, не подменяет p95/p99 или GPU/presented FPS.

## Промежуточная публикация

Пользователь явно разрешил commit и push текущей работы в `perf` во время измерений.
Готовая инфраструктура сохраняется отдельным коммитом; генерируемые результаты/эталоны не включаются частично.
Push `perf` не переносит изменения в `main` и не запускает Pages: workflow отслеживает только `main`.
Следующие измерения продолжаются; итоговый отчёт и baseline — отдельный checkpoint.
